## RCA

### P-01：CI の `npm ci` だけが失敗した

- なぜ 1：ロックファイルでは esbuild が 0.25 のままだった。一方、vite 8 は `^0.27 || ^0.28` を求めていて、CI の npm 10 がこの食い違いを弾いた。
- なぜ 2：古いロックファイルの上で `npm audit fix` と `npm install` を重ねたため、古い解決が残った。
- なぜ 3：手元では検出できなかった。当時のロックファイルで確かめると、手元の npm 11 では `npm ci --dry-run` が通り、npm 10 では失敗する。
- なぜ 4：手元は Node 26（npm 11）、CI は Node 22（npm 10）で、npm のメジャー版が違っていた。版をそろえる決まりがなかった。
- 根本原因：手元と CI で npm のメジャー版をそろえる仕組みがない。
- 再発防止策：`.nvmrc` で Node 24（npm 11 系）を指定し、CI とデプロイは `node-version-file: .nvmrc` で読む。CLAUDE.md に「npm のメジャー版をそろえる」と書く。

### P-02：キャッシュのせいで、出力の変化を見落とした

- なぜ 1：katex を 0.19 に上げたあとのビルドが、変換済みの記事のキャッシュ（`node_modules/.astro/data-store.json`）を使った。katex 0.16 の出力のまま比べていた。
- なぜ 2：Astro は設定や Astro 自体の版が変わるとキャッシュを消す。ビルドのログに「Content config changed / Clearing content store」と出ていた。一方、プラグインが使うライブラリの版が変わっただけでは消さないとみられる（推定。katex の版を変えたあとのビルドでは出力が変わらず、node_modules を作り直したあとのビルドでは変わった）。
- なぜ 3：比べる手順に「キャッシュを消してからビルドする」という段階がなかった。また、画面で確かめる前に、HTML の比較だけで結論を書いた。
- 根本原因：出力を比べる手順に、比べる前提（キャッシュ）をそろえる段階と、画面での確認がない。
- 再発防止策：`npm run build:clean`（キャッシュを消してからビルド）を追加した。CLAUDE.md に「依存や Markdown のプラグインを変えたあとの比較は `build:clean` で行い、数式とコードは画面でも確かめる」と書く。Claude のメモリーにも同じ注意を残す。

### P-03：main の CI の失敗に気づかなかった

- なぜ 1：`node-version: 22` は、実行するマシンにキャッシュされている 22 系を使う。マシンによって 22.23.3 と 22.23.4 が混ざっていた。
- なぜ 2：Astro 7 の要件の下限は 22.23.4 というパッチ版で、それより緩い指定をしていた。
- なぜ 3：main へマージしたあと、デプロイのワークフローだけを見て「成功」と報告した。同じコミットで動いた CI は確かめなかった。
- 根本原因：Node の版の指定が要件の下限より緩い。さらに、main へマージしたあとの確認が「デプロイの成功」だけになっていた。
- 再発防止策：`.nvmrc` で Node 24 を指定する（P-01 と同じ）。CLAUDE.md に「main へマージしたら、そのコミットで動いたすべてのワークフローの結果を確かめる」と書く。Claude のメモリーにも残す。
